# stardust improvement — every generated text must be editable in Experience Workspace

Self-contained spec for a general plugin improvement, written from the rwe.com
migration (2026-09-03). Everything here is site-agnostic; rwe numbers are
evidence. The objective is a hard property of stardust output: **any text an
author wrote in a DA document is inline-editable in Experience Workspace
(da.live canvas, "quick-edit") once the page is decorated by generated block
JS** — with the block looking the same while it is being edited.

Reference artifacts in this project (copy into the plugin):

- Probe: `stardust/scripts/ew-editability-probe.mjs` — instrument like DA →
  decorate → count survivors per block; `--simulate-editor` measures edit-mode
  style/height drift. Target location in the plugin:
  `skills/deploy/scripts/ew-editability-probe.mjs` (next to `block-roundtrip.mjs`).
- Reference conversions (before/after in git): `blocks/hero/hero.js` (+css),
  `blocks/spotlight/spotlight.js` (+css), `blocks/columns/columns.js`,
  `styles/styles.css` (edit-mode CTA repaint, `.affordance-wrap` variant).
- Ledger: `stardust/learnings.md` #15; journal 2026-09-03.

Plugin source: the marketplace clone at
`~/.claude/plugins/marketplaces/adobe-skills/plugins/stardust/` (adobe/skills,
v0.18.2 at time of writing). File paths below are relative to that folder.

## 1. Problem

On the migrated rwe home page, opened in `da.live/canvas#/paolomoz/rwe/index`,
clicking hero-carousel text or spotlight-ticker text did nothing, while the
`columns` body paragraphs were editable (its CTA was not). Measured with the
probe against `aem up`:

| page `/` (before) | authored texts | editable |
|---|---|---|
| hero | 12 | 0 |
| spotlight | 13 | 0 |
| columns | 5 | 2 |
| responsibility / cards / banner / press | 60 | 0 |
| default content | 12 | 12 |
| **total** | **102** | **14** |

Every block generated by stardust:deploy on this site fails the property; only
default content passes. The same census over all 27 blocks shows the causes are
systemic (25 blocks call `textContent`, 13 assign `innerHTML`, 16 clone, 23
`replaceChildren`).

## 2. Mechanism (verified against the da.live + da-nx sources, not the reports)

Files: da.live `blocks/canvas/editor-utils/editor-utils.js`,
`blocks/canvas/ew-editor-wysiwyg/ew-editor-wysiwyg.js`; da-nx
`nx/public/plugins/quick-edit/quick-edit.js`, `src/images.js`, `src/prose.js`,
`src/dom-index.js`, `src/selection.js`.

1. The canvas loads the page from the preview host in an iframe
   (`…preview.da.live/<path>?quick-edit=on&controller=parent`) and hands the
   quick-edit plugin the page's own `loadPage`.
2. On every document change `getInstrumentedHTML(view)` serialises the
   ProseMirror doc and stamps **`data-prose-index`** (the doc position) on every
   **outermost** `h1,h2,h3,h4,h5,h6,p,ol,ul,pre,blockquote`, `data-image-index`
   on every `img`, and `data-block-index` on every block `div`.
3. `setBody()` does `document.body.innerHTML = body; await ctx.loadPage(document)`
   — i.e. **every block's `decorate()` runs over the instrumented markup** —
   then `restoreBlockIndices()` repairs **only** `data-block-index` (matching by
   block class name). Nothing repairs `data-prose-index`.
4. `setupContentEditableListeners()` requests an editor for every surviving
   `[data-prose-index]`; `createEditor()` does
   `document.querySelector('[data-prose-index="N"]').replaceWith(editorParent)`
   where `editorParent = div.prosemirror-editor[data-prose-index] > div.ProseMirror`
   and ProseMirror renders the **doc node**: same tag, no classes, no inner
   `<span>`s, inline marks only (`strong`, `em`, `a`).
5. Cursor math uses the element's `textContent` length (`data-initial-length`).

Hence, per authored text, after `decorate()`:

| state of its `data-prose-index` | result |
|---|---|
| on exactly one element | editable |
| on zero elements (rebuilt from `textContent`/`innerHTML`, synthesized `<p>`, retagged element) | **dead**, silently |
| on several elements (clone slides) | editor attaches to the **first in DOM order** (often a hidden clone) |
| survives, but layout classes sit on the element or its spans | editable, but the look breaks **while editing** (classes die in the swap) |

Corollary that both reports missed: `cloneNode(true)` is *not* what kills
editing — the clone carries the attribute; that is exactly why `columns`
(clone-based) worked while `hero` (innerHTML/textContent) did not. Cloning is
still wrong (duplicates, stale identity), but the fix is "move", not "avoid
clone".

## 3. Root causes inside the plugin (what to change)

The generated blocks are correct implementations of the skill's own guidance;
the guidance is the bug.

| plugin text | problem |
|---|---|
| `skills/deploy/SKILL.md` § 2b **Template-slotted tier (#95)**: "holds the prototype section's inner DOM verbatim as a template literal and SLOTS the authored **values** into it by role — eyebrow **text** into the template's eyebrow node, heading into the `<h1>`…" | value-slotting copies text out of the authored node → every template-slotted block is 100 % dead (rwe hero, columns, header/footer). |
| § 8 **Block JS scaffold**: `function text(cell) { return cell.textContent.trim(); }`, "Build the prototype's DOM", "clone the cell's child nodes into a .actions wrapper", `block.replaceChildren(...newMarkup)` | scaffold teaches rebuild-from-text; CTA guidance clones the anchor (the index is on the `<p>`). |
| § 8 **#55** "clone `inner.childNodes` into your own `<h1>`" | childNodes carry no attribute → dead headline. |
| § 8 **#62/#71 `collectNodes()`**: "synthesize a `<p>` from the cell text" | synthesized elements are dead; in DA content the `<p>` always exists (pipeline `wrapTextNodes`), synthesis only ever fires in the off-pipeline harness. |
| § 5 buttons: "block JS just clones them as-is" | clone of the anchor loses the indexed paragraph. |
| § 8 **#70** "strip a matching leading glyph from the cloned text node" / any `.trim()` of displayed text | changes `textContent` length → cursor offsets wrong. |
| § "Reabsorb" section heads: "build the SAME `.section-head`… remove the wrapper" | must MOVE the wrapper's children, not rebuild. |
| No gate measures editability: `block-roundtrip.mjs` proves role fidelity only; `visual-diff`/`qa` never open the workspace. | the defect ships silently; found by the customer in the canvas. |

## 4. The contract (put in the skill verbatim, as a named section)

### Experience Workspace editability contract (EW1–EW8)

**EW1 — Move authored elements; never rebuild them.** Every authored
`h1–h6 / p / ul / ol / pre / blockquote / picture / img` is slotted into the
generated layout with `append()`/`prepend()`/`before()`. Never re-create it from
`textContent`/`innerHTML`, never `cloneNode` + discard, never retag (an authored
`<h2>` stays an `<h2>`; the ENCODE side authors the tag the design needs), never
`.trim()`/normalise displayed text. Discarding the emptied rows afterwards
(`block.replaceChildren(...)`) is fine — the nodes have already moved.

**EW2 — Wrappers carry layout classes; style through wrapper-descendant
selectors.** Because the editor swap re-renders the same tag *without classes or
spans*, `.card-title` on a generated `<div>` wrapping the authored `<h3>` +
`.card .card-title :is(h3, h4) { margin: 0; font: inherit; color: inherit }`
survives editing; `h3.card-title` does not. Put typography on the wrapper or in
the descendant rule; `color` must be set explicitly (global `h1–h6 { color }`
beats inheritance). Inner restructuring of the authored element (per-line
`<span>`s) is allowed only as a presentation refinement the wrapper does not
depend on (rwe hero: navy/white line spans; the wrapper carries the colour too).

**EW3 — CTAs move as their paragraph.** The index is on the `<p>`, not the
`<a>`: `actions.append(a.closest('p') || a)`. `decorateButtons()` already put
`.button.primary/.secondary` on the anchor before `decorate()` ran; those classes
die while editing, so the foundation ships an **edit-mode repaint** derived from
the authored marks (see § 5 Foundation) — zero effect on published pages.

**EW4 — Presentational clones strip instrumentation.** Carousel loop slides,
marquee duplicates, sticky copies: `clone.querySelectorAll('[data-prose-index],
[data-image-index]').forEach(strip)`. One element per index, and it must be the
visible one. Helper `stripInstrumentation(el)` goes in the scaffold.

**EW5 — Text-as-metadata is exempt, and declared.** Authored text that is never
displayed (icon/glyph keys, `label | value` keys, variant selectors, video/embed
source links, hidden config rows) needs no inline editability — it is edited in
the workspace's Content view. Declare each exemption in the block JSDoc with a
machine-readable tag (`@ew-exempt <p><a> video source (cell 2)`) so the gate can
whitelist it instead of failing.

**EW6 — Card-as-link: unwrap the authored inner anchor in the live DOM**
(`a.replaceWith(...a.childNodes)`) after reading its `href`; the indexed
paragraph survives, no nested anchors. Editor-rendered anchors inside such cards
get `color: inherit; text-decoration: none` under `.prosemirror-editor`.

**EW7 — Section heads reabsorbed from default content MOVE the wrapper's
children** (they are already editable as default content) and remove the empty
wrapper.

**EW8 — Re-entrancy.** `setBody()` re-runs `loadPage()` on a fresh body every
time; blocks that adopt sibling sections (tabs, accordions) must move those
decorated blocks whole and must not depend on module-level state from the
previous run.

Template-slotted tier (§ 2b) is redefined as **node-slotting**: the template
literal contains empty *slot containers* (`<div class="headline"></div>`), and
the authored elements are moved into them by role. Fidelity-by-construction is
preserved; value-slotting is removed.

## 5. Changes by file

### `skills/deploy/SKILL.md`

- **§ Target runtime**: new bullet "Experience Workspace instrumentation" —
  three sentences on § 2 above (what is stamped, that `decorate()` runs over it,
  that only surviving `[data-prose-index]` elements become editors). Link to the
  contract.
- **§ 2b decode tier**: rewrite Template-slotted as node-slotting (above); add
  "both tiers are subject to EW1–EW8; the gate is
  `ew-editability-probe`/`block-roundtrip --ew`".
- **§ 3 Foundation**: ship two foundation snippets in `styles.css`:
  (a) edit-mode CTA repaint —
  `.prosemirror-editor p > :is(strong, em) > a:any-link, .prosemirror-editor p > a:any-link:has(> :is(strong, em):only-child)`
  with the project's button declarations, `strong` = primary paint, `em` =
  secondary paint, on-media variants last in the file (see rwe `styles.css`);
  (b) the rule that any "styled text link" utility (`.affordance`, `.eyebrow`,
  `.meta`) also exists as a wrapper variant with **equal specificity** via
  `:where()` — `.affordance, .affordance-wrap :where(a)` — so moving an authored
  link into a wrapper does not change the cascade (rwe: a plain
  `.affordance-wrap a` silently flipped navy → teal because it now out-ranked
  `a:any-link`).
- **§ 5 Buttons**: replace "block JS just clones them as-is" with EW3.
- **§ 8 Block JS scaffold**: replace the scaffold with a move-based one —
  helpers `slot(target, ...nodes)` (append, never clone), `ctaOf(cell)`
  (`a.closest('p')`), `stripInstrumentation(clone)`; comment lines "1. query
  content, 2. create wrappers with layout classes, 3. MOVE authored nodes into
  wrappers, 4. `block.replaceChildren(...wrappers)`". Rewrite #55 (unwrap
  nested heading by *moving* the authored heading, never by cloning childNodes),
  #62/#71 (`collectNodes` returns existing elements only; the synthesized-`<p>`
  branch is a harness-only fallback and must be flagged), #70 (strip a doubled
  marker from the *generated* marker, never edit the authored text node). Add
  the contract section and the gate command right after the scaffold.
- **§ Local QA / Checklist**: new checklist lines — "EW gate exits 0 for every
  block (dead = 0 outside declared exemptions, duplicated = 0)"; "edit-mode
  simulation: no font/colour drift, block height Δ ≤ 2 px"; "no
  `textContent =`/`innerHTML =` on an authored element, no `cloneNode` of an
  indexed element without stripping".
- **§ Anti-patterns**: add "Value-slotting: copying authored text into template
  nodes. Looks perfect on the published page, is 100 % uneditable in the
  workspace, and no existing gate catches it."
- **§ References**: da.live editor-utils + da-nx quick-edit paths.

### `skills/deploy/scripts/`

- Add `ew-editability-probe.mjs` (from this repo). Two modes: URL mode (dev

### Field procedure for already-migrated sites (rwe follow-up)

1. `node stardust/scripts/ew-editability-probe.mjs <every migrated page> --verbose`
   to get the dead list per block.
2. Convert each block with the pattern in `blocks/hero/hero.js` /
   `blocks/spotlight/spotlight.js`; adjust the block CSS from element-class to
   wrapper-descendant selectors; keep the published render pixel-identical
   (screenshot before/after at 1440, `pixelmatch` = 0).
3. Re-run the probe with `--simulate-editor`; fix drift by moving colour/type
   onto wrappers.
4. Remaining on rwe `/`: responsibility (5), cards (45), banner (6), press (4).

## 7. Review of the two external analyses

`da-wysiwyg-playbook.md` — right about the symptom class and the
classify-and-rearrange principle; wrong on the mechanism in three places that
would misdirect a fix: (a) instrumentation is on the *editable elements*
(`p`/`h*`/lists), not on block rows/cells, so "move the row `<div>`" does not
help and losing a row is harmless; (b) DA holds no "live reference" — editors
are created by `querySelector` *after* `loadPage()`, so `cloneNode(true)`
works (with the duplicate caveat), the columns block proves it; (c) "author the
heading directly and let the block only add classes" is right for the tag but
adding the class **to the authored element** breaks the look during editing
(EW2). Its DA push/verify loop and the autoblock-steals-h1 caution are useful
and unrelated to this defect.

`Untitled` (generation-rules report) — mechanism is accurate and matches the
sources; R1–R7 are adopted as EW1–EW8 with two refinements: descendant
selectors from the wrapper are a simpler, specificity-safe alternative to the
inheritance-plus-reset recipe (R3), because the editor renders the same tag; and
the `body.quick-edit` gate for the CTA repaint is unnecessary — scoping on
`.prosemirror-editor` is already zero-cost on published pages and does not
depend on the bootstrap setting a body class. Its `updateDocument(ewEditorDoc.
_controllerCtx)` automation note is the right way to trigger instrumentation
in the real canvas; the probe here avoids needing the canvas at all.
