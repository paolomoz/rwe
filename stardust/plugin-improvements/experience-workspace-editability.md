# stardust improvement — every generated text must be editable in Experience Workspace

Self-contained spec for a general plugin improvement, written from the rwe.com
migration (2026-09-03, two rounds: 3 blocks, then 17 more). Everything here is
site-agnostic; rwe numbers are evidence. The objective is a hard property of
stardust output: **any text an author wrote in a DA document is inline-editable
in Experience Workspace (da.live canvas, "quick-edit") once the page is decorated
by generated block JS — and the block looks the same while it is being edited.**

## 1. Problem

On the migrated rwe home page, opened in `da.live/canvas#/paolomoz/rwe/index`,
clicking hero-carousel text or spotlight-ticker text did nothing, while the
`columns` body paragraphs were editable (its CTA was not). Measured with the
probe over a 29-page sample covering every block at least once:

| sample (29 pages) | authored texts | editable before | after round 1+2 |
|---|---|---|---|
| default content | 446 | 446 | 446 |
| 20 stardust blocks (cards, hero, accordion, companies, …) | 970 | 395 | 970 |
| declared exemptions (index-driven, derived, integration, structure-split) | 36 | 0 | 0 |
| **total** | **1452** | **841** | **1416** |

Every reconstructive or template-slotted block generated by stardust:deploy on
this site failed the property; only default content and blocks that happened to
move the authored `<ul>`/`<p>` (accordion bodies, icon-list, table) passed. The
census over 27 blocks shows the causes are systemic (25 call `textContent`, 13
assign `innerHTML`, 16 clone, 23 `replaceChildren`).

## 2. Mechanism (verified against the da.live + da-nx sources, not the reports)

Files: da.live `blocks/canvas/editor-utils/editor-utils.js`,
`blocks/canvas/ew-editor-wysiwyg/ew-editor-wysiwyg.js`, `blocks/shared/prose2aem.js`;
da-nx `nx/public/plugins/quick-edit/quick-edit.js`, `src/images.js`,
`src/prose.js`, `src/dom-index.js`, `src/selection.js`.

1. The canvas loads the page from the preview host in an iframe
   (`…preview.da.live/<path>?quick-edit=on&controller=parent`) and hands the
   quick-edit plugin the page's own `loadPage`.
2. On every document change `getInstrumentedHTML(view)` serialises the
   ProseMirror doc and stamps **`data-prose-index`** (the doc position) on every
   **outermost** `h1,h2,h3,h4,h5,h6,p,ol,ul,pre,blockquote`, `data-image-index`
   on every `img`, and `data-block-index` on every block `div`. `prose2aem`
   copies each table cell's innerHTML, so **every block cell contains a `<p>`**
   (the published pipeline unwraps single-paragraph cells to bare text; the
   runtime's `wrapTextNodes` re-wraps them, so `decorate()` sees a `<p>` in
   both worlds — but a gate that instruments published HTML must re-wrap too).
3. `setBody()` does `document.body.innerHTML = body; await ctx.loadPage(document)`
   — i.e. **every block's `decorate()` runs over the instrumented markup** —
   then `restoreBlockIndices()` repairs **only** `data-block-index` (matching by
   block class name). Nothing repairs `data-prose-index`.
4. `setupContentEditableListeners()` requests an editor for every surviving
   `[data-prose-index]`; `createEditor()` does
   `document.querySelector('[data-prose-index="N"]').replaceWith(editorParent)`
   where `editorParent = div.prosemirror-editor[data-prose-index] > div.ProseMirror`
   and ProseMirror renders the **doc node**: same tag, no classes, no inner
   `<span>`s, inline marks only (`strong`, `em`, `a`), hard breaks as `<br>`.
5. Cursor math uses the element's `textContent` length (`data-initial-length`).

Hence, per authored text, after `decorate()`:

| state of its `data-prose-index` | result |
|---|---|
| on exactly one element | editable |
| on zero elements (rebuilt from `textContent`/`innerHTML`, synthesized `<p>`, retagged element) | **dead**, silently |
| on several elements (clone slides) | editor attaches to the **first in DOM order** (often a hidden clone) |
| survives, but layout classes sit on the element or its spans, or the CSS path uses `>`/`:first-child` | editable, but the look breaks **while editing** (the swap inserts two wrapper divs and drops classes) |
| survives inside a `<button>` | editable in theory, unreachable in practice (the button swallows focus/click) |

Corollary that both external reports missed: `cloneNode(true)` is *not* what
kills editing — the clone carries the attribute; that is exactly why `columns`
(clone-based) worked while `hero` (innerHTML/textContent) did not. Cloning is
still wrong (duplicates, stale identity), but the fix is "move", not "avoid
clone".

## 3. Root causes inside the plugin (what to change)

The generated blocks are correct implementations of the skill's own guidance;
the guidance is the bug.

| plugin text | problem |
|---|---|
| `skills/deploy/SKILL.md` § 2b **Template-slotted tier (#95)**: "holds the prototype section's inner DOM verbatim as a template literal and SLOTS the authored **values** into it by role — eyebrow **text** into the template's eyebrow node, heading into the `<h1>`…" | value-slotting copies text out of the authored node → every template-slotted block is 100 % dead (rwe hero, columns, banner, contacts, events, header/footer). |
| § 8 **Block JS scaffold**: `function text(cell) { return cell.textContent.trim(); }`, "Build the prototype's DOM", "clone the cell's child nodes into a .actions wrapper", `block.replaceChildren(...newMarkup)` | scaffold teaches rebuild-from-text; CTA guidance clones the anchor (the index is on the `<p>`). |
| § 8 **#55** "clone `inner.childNodes` into your own `<h1>`" | childNodes carry no attribute → dead headline. |
| § 8 **#62/#71 `collectNodes()`**: "synthesize a `<p>` from the cell text" | synthesized elements are dead; in DA content the `<p>` always exists (see § 2.2), synthesis only ever fires in the off-pipeline harness. |
| § 5 buttons: "block JS just clones them as-is" | clone of the anchor loses the indexed paragraph. |
| § 8 **#70** "strip a matching leading glyph from the cloned text node" / any `.trim()` of displayed text | changes `textContent` length → cursor offsets wrong. |
| § "Reabsorb" section heads: "build the SAME `.section-head`… remove the wrapper" | must MOVE the wrapper's children, not rebuild. |
| No gate measures editability: `block-roundtrip.mjs` proves role fidelity only; `visual-diff`/`qa` never open the workspace. | the defect ships silently; found by the customer in the canvas. |

## 4. The contract (put in the skill verbatim, as a named section)

### Experience Workspace editability contract (EW1–EW10)

**EW1 — Move authored elements; never rebuild them.** Every authored
`h1–h6 / p / ul / ol / pre / blockquote / picture / img` is slotted into the
generated layout with `append()`/`prepend()`/`before()`. Never re-create it from
`textContent`/`innerHTML`, never `cloneNode` + discard, never retag (an authored
`<h2>` stays an `<h2>`; the ENCODE side authors the tag the design needs), never
`.trim()`/normalise displayed text. Discarding the emptied rows afterwards
(`block.replaceChildren(...)`) is fine — the nodes have already moved. When you
walk siblings while moving them, capture `nextElementSibling` **before**
`append()` (moving a node ends the walk otherwise — rwe companies dropped every
subsidiary link silently).

**EW2 — Wrappers carry layout classes; style the authored element through the
wrapper with descendant selectors.** The editor swap re-renders the same tag
*without classes or spans* and inserts **two wrapper divs**
(`div.prosemirror-editor > div.ProseMirror > <tag>`), so:
- rewrite `h3.headline { … }` as `.headline :is(h2, h3, h4) { … }` — same
  specificity, same cascade (the element keeps its global heading type and
  margins), and it still matches the editor's `<h3>`;
- never use child combinators or positional pseudo-classes on the path to an
  authored element (`.affordance > p`, `header > p`, `:first-child`,
  `:nth-child`); to exclude a moved CTA paragraph from a lede rule use
  `header p:where(:not(.affordance p))` (zero-specificity exclusion);
- only when the old rule itself set the type (a bespoke hero headline) does
  the wrapper carry `font-*` and the inner element gets `font: inherit;
  color: inherit; margin: 0`;
- `color` on the wrapper must be explicit when spans used to carry it (global
  `h1–h6 { color }` beats inheritance);
- inner restructuring of the authored element (per-line `<span>`s) is allowed
  only as a presentation refinement the wrapper does not depend on.

**EW3 — CTAs move as their paragraph.** The index is on the `<p>`, not the
`<a>`: `actions.append(a.closest('p') || a)`. `decorateButtons()` already put
`.button.primary/.secondary` on the anchor before `decorate()` ran; those classes
die while editing, so the foundation ships an **edit-mode repaint** derived from
the authored marks (§ 5 Foundation) — zero effect on published pages. Classes a
block itself adds to an authored anchor or list (`a.link-download`,
`ul.icon-list-items`) die the same way: style by element or attribute instead
(`.icon-list ul`, `a[href*=".pdf"]`).

**EW4 — Presentational clones strip instrumentation.** Carousel loop slides,
marquee duplicates, sticky copies: `clone.querySelectorAll('[data-prose-index],
[data-image-index]').forEach(strip)`. One element per index, and it must be the
visible one. Helper `stripInstrumentation(el)` goes in the scaffold.

**EW5 — Exempt text is declared, not silently dropped.** Three categories:
(a) *text-as-metadata* never displayed (glyph keys, `label | value` keys,
variant selectors, video/embed source links, hidden config rows); (b) *derived
text* (an ISO date re-rendered as day/month spans) — prefer authoring the
displayed form; (c) *index/API-driven blocks* whose authored rows are only the
no-JS fallback (press listings, job lists, forms, maps). Declare each in the
block JSDoc with a machine-readable tag (`@ew-exempt <p> ISO date (cell 1) —
derived`) so the gate whitelists it. A fourth shape — one authored paragraph
rendered as N elements (a breadcrumb trail) — cannot be made editable by the
block: the ENCODE side must author a `<ul>` (a list is one editable unit).

**EW6 — Card-as-link: unwrap the authored inner anchor in the live DOM**
(`link.replaceWith(...link.childNodes)`) after reading its `href`; the indexed
paragraph survives inside the card `<a>`, no nested anchors on the published
page. The editor re-renders the inner link while editing, so the foundation
ships `a .prosemirror-editor a:any-link { color: inherit; text-decoration: none }`.

**EW7 — Interactive containers cannot host the editor.** A `<button>` (or
`<summary>`) swallows focus and clicks: an accordion title moves into a sibling
`div.accordion-title`, the whole headline row takes the click handler, and the
button becomes a chevron-only toggle with an `aria-label`. Content hidden at
rest (collapsed panels, inactive tabs, non-active slides) is editable but only
reachable after the author opens it — keep those controls working inside the
workspace (link navigation is blocked there, buttons are not).

**EW8 — Section heads reabsorbed from default content MOVE the wrapper's
children** (they are already editable as default content) and remove the empty
wrapper.

**EW9 — Re-entrancy.** `setBody()` re-runs `loadPage()` on a fresh body every
time; blocks that adopt sibling sections (tabs, accordions) must move those
decorated blocks whole and must not depend on module-level state from the
previous run.

**EW10 — Default content styling follows the same selector rules.** Section
styles on prose (`main .section.x .default-content-wrapper > p:first-child`,
`p:has(picture) + p`) drift in edit mode for the same two-wrapper reason; use
descendant selectors and avoid positional pseudo-classes on prose elements.

Template-slotted tier (§ 2b) is redefined as **node-slotting**: the template
literal contains empty *slot containers* (`<div class="headline"></div>`), and
the authored elements are moved into them by role. Fidelity-by-construction is
preserved; value-slotting is removed.

### Field procedure for already-migrated sites (what was done on rwe)

1. Build a covering sample: for every block class in `content/**`, one or two
   pages; `node stardust/scripts/ew-editability-probe.mjs <urls> --json` →
   aggregate dead per block.
2. Capture baseline element screenshots of every block instance at 1440 with
   `body > header` hidden (Playwright, `reducedMotion: 'reduce'`).
3. Convert each block with the pattern in § 4; rewrite the block CSS
   element-class selectors to wrapper-descendant form.
4. Re-shoot, `pixelmatch` = 0 per instance (live-widget iframes excepted);
   re-probe with `--simulate-editor`; fix drift by moving the offending
   selector to descendant form.
5. Remaining dead texts must all be declared exemptions; commit per group.

## 7. Review of the two external analyses

`da-wysiwyg-playbook.md` — right about the symptom class and the
classify-and-rearrange principle; wrong on the mechanism in three places that
would misdirect a fix: (a) instrumentation is on the *editable elements*
(`p`/`h*`/lists), not on block rows/cells, so "move the row `<div>`" does not
help and losing a row is harmless; (b) DA holds no "live reference" — editors
are created by `querySelector` *after* `loadPage()`, so `cloneNode(true)`
works (with the duplicate caveat), the columns block proves it; (c) "author the
heading directly and let the block only add classes" is right for the tag but
adding the class **to the authored element** breaks the look during editing
(EW2). Its DA push/verify loop and the autoblock-steals-h1 caution are useful
and unrelated to this defect.

`Untitled` (generation-rules report) — mechanism is accurate and matches the
sources; R1–R7 are adopted as EW1–EW10 with refinements: descendant selectors
from the wrapper (not the inheritance-plus-reset recipe of R3) are the primary
tool, because the editor renders the same tag and the inner element should keep
its global type; the two-wrapper insertion forbids child combinators; the
`body.quick-edit` gate for the CTA repaint is unnecessary — scoping on
`.prosemirror-editor` is already zero-cost on published pages. Its
`updateDocument(ewEditorDoc._controllerCtx)` automation note is the right way to
trigger instrumentation in the real canvas; the probe here avoids needing the
canvas at all.
